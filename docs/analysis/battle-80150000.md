# BATTLE.BIN 0x80150000–0x80157FFF + in-place patches: what ReMixed's code does

Scope: ReMixed's new code in BATTLE.BIN at RAM 0x80150000–0x80157FFF (about 70 routines and
fragments), plus in-place patches to vanilla BATTLE.BIN code that I ran into at hook sites.
Method: read each vanilla hook site (`tools/disasm.py --both`), then the ReMixed routine.
Breadth first: every cluster has a one-line verdict. Confidence levels are honest. "Low"
means "this is what the code does, but I'm not sure what feature it serves".

Most "routines" here are **fragments**, not functions: vanilla code does `j 0x8015xxxx`, the
fragment does a few instructions and jumps back. A port has to hook the *vanilla event*
(damage step, menu check...), not copy the fragment.

## 0. Reference facts used below (derived from the code, verify before relying on them)

pointer). Confirmed while reading:

Status bit layout (5 bytes): b0 0x40 Crystal 0x20 Dead 0x10 Undead 0x08 Charging 0x04 Jump
0x02 Defending 0x01 Performing; b1 0x80 Petrify 0x40 Invite 0x20 Darkness 0x10 Confusion
0x08 Silence 0x04 Blood Suck 0x02 Cursed 0x01 Treasure; b2 0x80 Oil 0x40 Float 0x20 Reraise
0x10 Transparent 0x08 Berserk 0x04 Chicken 0x02 Frog 0x01 Critical; b3 0x80 Poison 0x40 Regen
0x20 Protect 0x10 Shell 0x08 Haste 0x04 Slow 0x02 Stop 0x01 Wall; b4 0x80 Faith 0x40 Innocent
0x20 Charm 0x10 Sleep 0x08 Don't Move 0x04 Don't Act 0x02 Reflect 0x01 Death Sentence.

Support byte 0x92 bits: 0x80 Monster Skill, 0x40 Defend, 0x20 Equip Change, 0x10 **0x1E1**,
0x08 Short Charge, 0x04 Non-charge, 0x02 **0x1E4**, 0x01 **0x1E5** (Dancer/Oracle-copy innate).
0x90: 0x80 Half MP, 0x40 **Gained JP Up = 0x1CF (Thief innate, "Banditry")**, 0x20 Gained EXP
Up, 0x10 Attack UP, 0x08 Defense UP, 0x04 MA UP, 0x02 MDef UP, 0x01 Concentrate.

**Action globals**
- 0x80192D94 attacker unit ptr, 0x80192D98 target unit ptr.
- 0x80192D90 target action-result ptr (= target+0x18C), 0x80192D8C attacker's own result ptr.
  Result struct: +0 hit flag, +4 HP damage, +6 HP heal, +8 MP damage, +0xA MP heal, +0xE
  triggered reaction id, +0x1B..+0x1F statuses added, +0x20..+0x24 statuses removed, +0x25
  flags (0x80 HP dmg, 0x40 HP heal, 0x20 MP dmg, 0x10 MP heal, 0x08 status change).
- 0x801938CE = XA, 0x801938D0 = YA (Defense UP / Protect multiply 0x801938CE by 2/3).
- 0x801938D6 (u16) current ability id; 0x801938D8 weapon item id in use (0x80150DF0 /
  0x80155CF4 return its **item type** from the item table 0x80062EB8+5).
- 0x801938F0–0x801938FD = copy of the ability's 14-byte attribute entry (F3 flags1: 0x04
  "weapon strike"; F6 flags4: 0x08 requires sword, 0x04 "requires materia blade"; F7 element;
  F8 formula; **F9 X; FA Y; FB inflict-status id**).
- 0x801938FE–0x80193905 = copy of the weapon's 8-byte entry (0x80193900 weapon formula,
  0x80193902 WP, 0x80193904 element).
- **Formula jump table: 0x8018F610 + 4 × formula id.**

**Helpers**: 0x80180AFC get unit ptr; 0x8013B590 read event variable; 0x8002230C rand;
0x8005E22C copy 20 bytes; 0x8005E254 copy n bytes; 0x80154000 (new) copy n bytes;
0x80188510 physical evade check (≠0 = evaded); 0x80187EB4 / 0x801870FC / 0x80186FD0 /
0x801886A4 / 0x80185A9C / 0x80185FA4 are the vanilla damage-formula building blocks (XA/YA
load, modifiers, hit roll, apply).

**Possible option toggles.** Several new routines start with a constant test such as
`ori at, zero, 0x0 ; beq at, zero, skip` (0x80150340) or `ori t3, zero, 0x1 ; beq t3, zero`
(0x80155198). The immediates may be patched at runtime by the Extra Options menu. The menus
agent should check whether OPTION.OUT/SCUS writes into these addresses. Other SCUS bytes read
as flags here: 0x8005776C (percentage), 0x8005776F (&0x0C), 0x80057718, 0x800578CE (&3),
0x80057927 (&0x10), 0x80057929 (&0x08/&0x10), 0x8005792B (&3), 0x8005771C/0x80057720/0x8005777C.

## 1. New ability formulas (formula table repoints) — high confidence on the wiring

ReMixed rewrote 7 entries of the formula table at 0x8018F610:

| Formula | Now → | Used by (ReMixed ability table) |
|---|---|---|
| 0x11 | vanilla stub 0x80189124 (`jr ra`) now jumps to **0x80152DC0** | 0x0FA (was formula 0x4E) |
| 0x13 | **0x80155B08** | 0x0DB (new; vanilla slot "Teleport 3: Send") |
| 0x19 | **0x80152BF0** | 0x02D (new, X=4 Y=64) |
| 0x1A | **0x80153500** | Magic Ruin, Speed Ruin, Power Ruin, Mind Ruin |
| 0x27 | **0x80151480** | Gil Taking (0x6C), 0x133 |
| 0x2D | 0x8015D200 (other agent's range) | Stasis Sword… Holy Explosion, Local Quake, 0x028, 0x0DC, Meteorain, Cherry Blossom |
| 0x39 | **0x80155BCC** | 0x0B8 (new; vanilla "Summon Angel" slot). Yell moved to 0x3B |
| 0x46 | **0x80153020** | Braver, Cross-slash, Omnislash, Poison Nail, **new 0x165–0x16E** |
| 0x49 | repointed to another vanilla routine (0x8018A278, was 0x80188288) | — |

What each one does:

- **0x46 → 0x80153020 "weapon skill, X/16 power"** (high). Physical evade check, then the
  ability's element (if any) replaces the weapon element. If the weapon's formula is 4 it goes
  through vanilla 0x80188C34; otherwise it runs a normal weapon-damage chain plus 0x801535A0.
  0x801535A0 sets 0x801938D9=1 when the attacker has Two Hands (0x91&0x02), the weapon allows
  two hands (weapon flag 0x04) and exactly one hand holds a weapon, i.e. it applies the
  two-hands bonus. On hit it inflicts the ability's status, applies damage, then
  **0x8015241C: HP damage × X / 16** (skipped if X=0). The new 0x165–0x16E have X=4..20, so
  25%–125% weapon damage.
- **0x11 → 0x80152DC0 "elemental weapon strike + stat change"** (high; corrected on 2026-11-02:
  the "status" byte is a stat mask and Y the amount, see below). Evade check. The weapon
  element is OR-ed with the ability element. Entered with v0=0: normal weapon XA, with the
  ability's Y zeroed while the damage is built. Entered with v0≠0 (from the other agent's
  0x8015D820): **XA = attacker MA, YA = weapon WP** (magic-sword style). On hit, lowers the
  target's stats in the ability's "status" byte (a mask) by Y (0x80186CA4), then sets the
  HP-damage or "no damage" flag.
  - The status call (0x80186CA4) is ReMixed's own routine written over vanilla code:
    if the target has Maintenance (support byte +0x91 & 0x04) the hit is cancelled;
    otherwise it writes Y into the result's stat-change bytes (+0x12 up: Speed, CT, PA, MA,
    Brave, Faith, as vanilla's Tailwind, Stall, Shout, Steel, Praise and Preach write them;
    bit 7 raises, else lowers) selected by the mask, which
    the status-chance mechanic (0x8015C500) reads. It doesn't inflict anything itself.
- **0x18 → 0x80152A30**: vanilla formula 0x4E (0x8018A420), then the knockback
  routine 0x801843EC (rewritten by ReMixed: MECHANICS.md, "Knockback rules"), which
  only acts for single-target actions (0x801938EC == 1). Wind Soul.
- **0x13 → 0x80155B08 "sacrifice strike"** (medium). Evade check. XA = PA, YA = MA, then
  weapon-type adjustment 0x80155D20 (Knight Sword/Katana: XA × Brave/100; Axe: XA ×
  (100−0x801938D3)/100). Then the normal target-side modifiers. On hit: **target takes extra
  damage = attacker Max HP / 3, and the attacker takes Max HP / 3 recoil** (written into the
  attacker's result struct).
- **0x39 → 0x80155BCC "ranged strike with falloff + recoil"** (medium). Evade check, vanilla
  XA load, weapon-type adjustment. 0x80155DA0 reduces YA with distance:
  YA ×= (16 − (X+1)·(d−1)) / 16, with d = Chebyshev distance (X=4 for 0x0B8). On hit the
  **attacker takes Max HP / 5 recoil**.
  - Recoil plumbing: 0x80152450 sets a one-byte static (stored inside a code word at
    0x8015247C). The patch at 0x8018BB24 → 0x80152480 replaces vanilla 0x8018ADF4, which
    *resets* both result structs (0x8018BD74 resets one: fields zeroed, hit = 1) and then
    clears the attacker's hit flag. ReMixed's version resets the attacker's only while the
    static isn't 2, and never clears its hit flag. The recoil formulas set that flag
    themselves, which is what gets the attacker's result applied. (Corrected 2026-11-02:
    first read as "applies".) The remaster applies an attacker result whose hit flag is set
    (its Chant, formula 0x3C, damages the caster that way), so the port needs no plumbing.
- **0x1A → 0x80153500 Ruins** (medium). If the ability has an inflict-status id it falls back
  to the vanilla stat-break body (0x801892AC); this covers Speed/Power/Mind Ruin. Otherwise
  (**Magic Ruin**) it builds magic damage, then copies the HP-damage/heal word to the MP
  fields and halves the HP fields (rounding up). Net effect: **Magic Ruin deals full damage to
  MP and half to HP**.
- **0x27 → 0x80151480 Gil Taking / "Shine Lover"** (medium). If the ability has the
  "weapon strike" flag (0x801938F3 & 0x04, as ability 0x133 does), it's a weapon attack: evade
  check unless the weapon is a gun, weapon damage, elemental step when attacker and target are
  on different teams, hit/damage. Then flag bit 0x01 is set in both result structs. Otherwise:
  evade check → the steal setup 0x80189828 → 0x80188B14 → 0x80186744. (Corrected 2026-11-03: 0x80189828 isn't
  vanilla's Gil Taking any more; ReMixed rewrote it in place into the setup formula 0x26 also calls: XA = Speed,
  YA = X, +10 with Banditry, X doubled while 0x80096214 is 2.)
- **0x19 → 0x80152BF0 "echo the attacker's queued ability at Y/128"** (low-medium). Sets
  0x801938E9=1 and calls 0x8018AD58(1). Copies the attacker's queued ability's animation id
  (table 0x801B63F0, indexed by attacker+0x174) onto this ability. Then scales the four
  HP/MP fields of both result structs by the ability's Y/128 (0x02D: Y=64, so half power).

**Port notes.** On the remaster these are formula hooks: register custom formula ids, or
patch the ability → formula dispatch, and implement each in C#. The weapon-chain steps map
onto the remaster's own damage pipeline; the ReMixed-specific parts are the multipliers
(X/16, MaxHP/3 or MaxHP/5 recoil, distance falloff, Magic Ruin's HP/MP split, Y/128 echo).

## 2. Per-ability weapon-type requirements — high

- **Routines**: 0x80153BCC (hooked from 0x8019A900) and 0x80153C8C (hooked from 0x80181A28).
- **Tables**: 0x80154030 (368 bytes, one per ability: mask index or 0xFF) and 0x801541A0
  (16 u32 masks, bit = 0x80000000 >> item type).
- **What vanilla did there**: tested ability-attribute byte 6 & 0x08 "requires sword". Hook
  0x8019A900 is the action-menu enable check; 0x80181A28 is in the AI / usable-ability check.
- **What ReMixed does**: if the ability's table entry isn't 0xFF, the right-hand (unit+0x1D)
  or left-hand (unit+0x1F) weapon's item type must be in the mask, otherwise the ability is
  disabled. When it passes, vanilla's remaining checks still run.
- **Masks**:
  - 0: Sword/Knight Sword. Holy Sword skills (Stasis Sword…Holy Explosion), 0x0EA–0x0F7 and
    0x100 (Mighty Sword set).
  - 6: Sword/KS/Katana/Axe. 0x028, Dark Sword, Night Sword, 0x0B5, 0x0B8, 0x0DB.
  - 7: Knife/Ninja Blade/Sword/KS/Katana/Axe/Flail. Braver…Cherry Blossom.
  - 8: Sword/KS/Spear. Shellbust Stab…Icewolf Bite and the 4 Ruins.
  - 9: Spear. Blow Fire (0x144).
  - New 0x165–0x16E, in pairs: knife/ninja/rod/bag; sword/KS/katana; axe/staff/flail;
    spear/pole/cloth; gun/crossbow/bow.
- **Port**: a data table plus a hook on "can this unit use ability X" (menu and AI). Probably
  replaces the "Requires Sword / Materia Blade" checks.

## 3. Defense Aura / Warding Aura (Defense UP / Magic Defense UP) — high

- **Entry points**: 0x801862E4 (vanilla: target Defense UP → XA×2/3) and 0x80186334 (target
  MDef UP → XA×2/3). Both now call 0x80151580 and then 0x80151640 (the ×2/3).
- **0x80151580(target, mask)**: gets the target's tile (0x8017C158), then checks the 4
  orthogonally adjacent tiles with vanilla 0x80182508 (unit on tile x,y,height of team
  target+5 with support byte matching the mask).
- **Effect**: the 2/3 reduction applies when the target has the support itself *or* an
  adjacent ally has it. Defense UP covers physical, Magic Defense UP covers magical.
- ReMixed generalized 0x80182508 (vanilla's Monster Skill check, +0x92 & 0x80) for this and
  for its Monster Skill rework: the support test is the word at +0x90 & a mask passed in t0,
  and a neighbour in status group 1 (0x8005E1B0(unit, 1)) doesn't count. It still needs the
  target's current team (+5 & 0x30) and a height within 5 (0x8017C158's +6).
- **Port**: damage-calc hook on the target-side modifier step. Check the 4 neighbours for
  allies with the support.

## 4. Gendered Bard/Dancer slots (Dark Knight) — medium-high

The job-unlock function is SCUS 0x8005DC14 (job levels → unlocked-job bitmask; 0x40 = Bard
slot, 0x20 = Dancer slot). Vanilla clears Dancer for males and Bard for females. ReMixed
routes those two branches (through the SCUS dispatcher 0x8002705C/0x800270C0, which picks the
BATTLE or WORLD copy by checking the overlay) to:
- **0x80152000 (male)**: Dancer bit set if the job levels meet the new requirement row at
  SCUS 0x80027100. Nibbles: Chemist 2, White Mage 2, Black Mage 2, Time Mage 2, Summoner 4,
  Mediator 4, Oracle 2.
- **0x801502C4 (female)**: Bard bit set if they meet row 0x80027110. Nibbles: Squire 2,
  Chemist 2, Knight 8, Black Mage 8, i.e. Dark Knight's requirement.

New jobs behind the slots: **job 0x37** (Dark Knight stats, skillset 0x4E) is the female Bard
slot, and **job 0x38** (vanilla Bard's stats, Dance-like skillset 0x4D, innate 0x1E5) is the
male Dancer slot. Glue code:
- 0x801525A0 (from 0x8017EA28): job id → generic index; job 0x38 on a male → 18, job 0x37 on
  a female → 17, else job−0x4A.
- 0x80152750 (from 0x801818EC): uses job 0x38's or 0x37's table entry for the checks there,
  by gender.
- 0x80152500 (JOBSTTS.OUT calls into 0x801E0390): remaps id 0x37 → 0x5B on non-males and
  0x38 → 0x5C on non-females, so the job screen shows the gender-correct job.

Port: remaster job-unlock rule plus two extra job entries. Mostly data; one hook on unlock
evaluation.

## 5. Banditry (Thief innate 0x1CF, vanilla "Gained JP Up") — medium

Corrected on 2026-11-02: Banditry doesn't steal. ReMixed's "Back Attacks" option reads
"attacking from behind can grant critical hits... if using Mug or Banditry".

- **0x80151840** (from ReMixed's rewrite of the critical step 0x801864F8, at 0x80186520):
  builds trigger flags. Flag 2 is set when the effective formula (0x801938E5) is below 7 (a
  basic attack) or 0x27 (Mug), the attack comes from behind (0x801938E2 & 2), the option byte
  0x80057929 doesn't say vanilla (& 0x08), and either says everyone (& 0x10), or the attacker
  has **support 0x90&0x40 (0x1CF)**, or the formula is 0x27. Flag 4: the attacker moved this
  turn (+0x187 bit 7), has movement 0x95&0x20 (0x1F8 Momentum) and a melee weapon (type below
  10 or 15–18), and 0x80096214 isn't 2.
- **0x80160440** (the rest of the critical step): with the vanilla 4% roll in flag 1, a flags
  value of 4 only marks a critical and knocks back; otherwise XA += the roll's random part
  (flag 1) plus, for flag 2, XA/2 (no weapon, knife, crossbow, bow) or XA/4; a critical either
  way (result +1), and a knockback (0x801843EC) only for flags 1 or 4.
- **0x80151700** belongs to Counter Steal (0x1B7; the reaction builder's jump table at
  0x80174134 starts at 0x1B7), not Banditry: against an enemy human (target team differs,
  gender 0x80/0x40), it rolls r = rand>>8 and picks a steal by band, falling through when the
  slot is empty:
  - <24: Steal Weapon 0x71 (weapon in a hand)
  - <48: Steal Shield 0x70
  - <72: Steal Helmet 0x6E
  - <96: Steal Armor 0x6F
  - <120: Steal Accessory 0x72
  - otherwise: Gil Taking 0x6C

  It then queues the steal through vanilla 0x8017E3DC (a1=0x0E).
- **0x80150E20** (from 0x8018199C, the AI's ability list only): with support 0x1CF, ability
  0x6C (Gil Taking) is swapped for 0x133 (Mug: formula 0x27's weapon-strike version, attack +
  steal gil; otherwise in monster skillsets 200–202).
- **0x80150CB8** (end of REQUIRE.OUT 0x801C7354): flushes a 256-entry per-item counter at
  0x80150BA0 into the party inventory (0x800596E0+item), keeping owned + equipped ≤ 99, then
  clears it. Its writer is the rewritten taking step (0x8018D490): items stolen from the player's units
  (MECHANICS.md, Taken equipment isn't lost; ported for the steals).
- **Port** (done): the back-attack critical in the remaster's critical step (0x305EB4), and
  the AI's Mug through its ability lists' calls to the skillset (0x275860).

## 6. Swap Ability Preview Targets — medium

- **0x80153100 / 0x8015311C** (from 0x80076C98, player targeting loop): when the button bit
  0x80 is pressed, gets the list of units in the ability's area (0x8017D850 into a buffer at
  0x80153228). It finds the currently previewed target, advances to the next one (wrapping),
  stores it in 0x80153220/0x80153224 and plays sounds (0x8014C940 0x0D/0x0C).
- **0x80153240** (from 0x8006E664): while that state is active, substitutes the selected unit
  for the preview's target pointer.
- **0x80153260** (ATTACK.OUT 0x801C9EDC): reads event variable a0, falls back to var 0x33
  when outside 1..120 (preview-related text/var selection).
- **Port**: UI hook in the targeting/preview screen: cycle the preview through all units in
  the area.

## 7. Cross / Scene Skip (hold to fast-forward events) — medium-high

0x80045944 is read as the held-pad word. Mask 0x840 is two buttons. Each fragment makes the
event code take its skip path while the buttons are held:
- 0x801509FC (from 0x801316CC): OR-s held &0x840 into the pad test (mask 0x160 → 0x960).
- 0x80150A14 (from 0x8013133C): forces text mode bits = 3 (instant text) while held.
- 0x80150A38 (from 0x801326F0): zeroes a wait counter while held.
- 0x80150A48: adds 32767 to a timer while held.
- 0x80150A78 (from 0x8012FBC8): zeroes s5 and 0x8016A404 (wait) while held.
- 0x801532B0 (from 0x801314E0): for text codes 0xF8/0xFC–0xFF, clears a pending wait
  (0x801533F0 flag and 0x80165FB4).
- 0x801509C4 (from 0x80138F10): flag 0x8015029E forces sp+272 = 1 (dialog advance) and is
  then cleared. It is set by 0x80150AA0 (below).

Port: probably skip. The remaster has its own text/scene skip; check before porting.

## 8. Unit snapshot / restore around the move phase ("undo move"?) — low-medium

- **0x80153D58** (from 0x8007241C, after the active unit's move-range setup): if flag
  0x8015029F ≠ 0xFF, the unit hasn't acted (unit+0x187 & 4 clear) and 0x8017DCA8(x,y,z,0x41)
  returns −1, copies the active unit into a backup at 0x80153400: 6 bytes of its battle
  object (+0x140), byte 5, 0x21–0x39, 0x4E–0x6C, 0x72–0x80, 0xDC–0x12B, 0x1BB–0x1BF, 0x182.
  Then sets 0x8015029F=1.
- **0x80153E40** (from 0x80074D14, the cancel branch of the turn menu): if the unit is in
  state 0x90 it clears the state and runs 0x801561C0. Otherwise, when a snapshot exists and
  nothing happened, it copies everything back (restoring position, HP/MP, statuses), checks
  for a unit on the same tile (0x8007D0A0) and calls 0x80075F10 to re-place units.
- **0x80156000 / 0x80156100**: a second, smaller save/restore set (CT 0x39, statuses
  0x58–0x6C, queued action 0x16E–0x17F, 0x15D, 0x1BB–0x1BF, battle object +0x140) into
  0x80153400+164. 0x80156000 is called from 0x8017FF00.
- 0x801521CC/0x801521DC (from 0x80072214/0x80072170) reset 0x8015029F to 0 at turn setup.
- My reading: it lets a move be cancelled even after the move triggered things vanilla
  normally commits to (Move-HP Up, Move-Find, traps…). Read again 2026-11-04: it is a move undo
  (the restore also re-places the units and a boarded mount, 0x80156100; a failed Teleport
  roll skips the backup, 0x80176964). Not ported: the remaster's enhanced mode has its own
  Reset Move (MECHANICS.md, Move undo).

## 9. Monster/new-ability tables in the other agent's area

- 0x80155E40 (from 0x801852F4) and 0x801529A0 (from 0x80188CC8 / 0x8015E790): table
  **0x8015E690[ability − 0x190]** (14 entries). Bit 0x80 = "can't be evaded"; the low 7 bits
  are some other per-ability parameter used at 0x80188CC8. Only 0x19C (Aimed Shot) has 0x80;
  0x192 has 93 and 0x19D has 43, all gun skills.
- 0x80155E1C (from 0x801852EC): **attacks ignore evasion when the attacker has Concentrate,
  is Transparent (0x5A&0x10), or uses a table-flagged ability**. Vanilla checked only
