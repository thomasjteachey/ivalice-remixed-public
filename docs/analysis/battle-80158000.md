# BATTLE.BIN new code 0x80158000–0x801610D4 (ReMixed v1.2.64.23)

Scope: ReMixed's new routines in BATTLE.BIN from 0x80158000 to the end of
the new code (last block ends 0x801610D4; nothing after that changed).
0x8015C000–0x8015C0FF, 0x80159DCC–0x80159F94, 0x8015D350–0x8015D373,
0x8015D940–0x8015D9F7, 0x8015E900–0x8015E9BF, 0x8016068C–0x801606DB and
0x8015F600+ are data tables, not code.

Method: entry points from `data/remixed/hooks.csv`, vanilla code read
around each hook, ReMixed routine read. A scratch annotating disassembler
(not in the repo) resolved lui/addiu pairs to absolute addresses.

Bit names for abilities: support byte 0x90 = 0x1CE Half of MP(0x80),
0x1CF Gained JP Up(0x40), 0x1D0 Gained Exp Up(0x20), 0x1D1 Attack UP(0x10),
0x1D2 Defense UP(0x08), 0x1D3 MA UP(0x04), 0x1D4 MD UP(0x02),
0x1D5 Concentrate(0x01). 0x91 = Train(0x80), Secret Hunt(0x40),
Martial Arts(0x20), Monster Talk(0x10), Throw Item(0x08), Maintenance(0x04),
Two Hands(0x02), Two Swords(0x01). 0x92 = Monster Skill(0x80), Defend(0x40),
Equip Change(0x20), 0x1E1(0x10), Short Charge(0x08), Non-charge(0x04),
0x1E4(0x02), 0x1E5(0x01). ReMixed reuses several of these slots (see below).

Formula/action globals (from vanilla use): 0x80192D90 = pointer to the
target's action-result block (+4 HP dmg, +6 HP heal, +8 MP dmg, +0xA MP
heal, +0x1B..0x1F statuses added, +0x20..0x24 statuses removed, +0x25
result flags: 0x80 HP dmg, 0x40 HP heal, 0x20 MP dmg, 0x10 MP heal,
0x08 status); 0x80192D94 = attacker unit; 0x80192D98 = target unit;
0x801938CE = XA, 0x801938D0 = YA, 0x80193902 = WP, 0x801938D8 = weapon
item id, 0x801938D4 = skillset of the action, 0x801938D6 = ability id,
0x801938F0..0x801938FD = copy of the ability's 14-byte attribute record
(0x801938F7 element, 0x801938F8 formula, 0x801938F9 X, 0x801938FA Y,
0x801938FB inflict-status id), 0x80193906..0x8019390B = copy of the
inflict-status record (byte 0 flags). 0x8018F5FC != 0 means "simulation"
(AI / preview pass: no random rolls, no side effects). Formula jump table
at 0x8018F614 (0x64 entries; ReMixed adds entry 0x64 → 0x8015D700).
Map tiles: 0x8018F8CC + 8 × (X + Y×width + 256×level), width at
0x800E4E9C; tile byte 0 & 0x3F = surface (0x12 lava), byte 3 >> 5 = depth.
Event variables: 32-bit array at 0x8005771C; story progression is event
var 0x6E (from community knowledge; medium). Party roster: 0x80057F74,
0x100 bytes per unit, 20 units. Inventory counts: 0x800596E0[item].
Helpers: 0x8002230C rand (BIOS), 0x8005E0CC(n,p) returns 1 with
probability (n−p)/n, 0x8005E254 memcpy(src,dst,n), 0x8013B590 get event
var, 0x8013B644 set event var.

ReMixed "Extra Options" bytes seen read here: 0x80057927 (bits 0x01,
0x02, 0x20), 0x80057928 (0x80), 0x80057929 (0x08, 0x10, 0x40, 0x80),
0x8005792A (0x40), plus 0x80057718 bit 0x40 and the word 0x80057774.
Which menu option each bit is should come from the SCUS/OPTION.OUT side.

## 1. Knockback landing: lava and water (Enhanced Knockback?)

- Routines: 0x801581A0 (entry from 0x8018AE94), 0x801580A0 (entry from
  0x8018AEF4). Uses 0x80157F80 (other agent: tile pointer under unit).
- Vanilla there: the fall-damage step after knockback. If the target isn't
  dead/crystal/stone and actually fell, damage =
  (fall height/2 − Jump) × MaxHP / 10, capped at 999.
- ReMixed:
  - Before that: if the landing tile is lava (surface 0x12) and the target
    lacks movement bits 0x95&0x88 (0x1F6 "Move in Water" slot or Float),
    damage = 999.
  - After vanilla's formula: Float status → 0; Float movement ability
    (0x95&0x08) → 0; with 0x1F6 (0x95&0x80) → unchanged; otherwise by
    water depth of the landing tile: depth 0 unchanged, depth 1 ×75%,
    depth 2 ×50%, depth 3+ → ×25% if the unit has 0x95&0x50 (Walk on
    Water / Move Underwater slots), otherwise 999 (drowns). Cap 999.
- Confidence: high on logic. The bit→ability mapping for 0x95 follows the
  vanilla layout; ReMixed may have renamed those movement abilities.
- Remaster: hook the knockback fall-damage calculation; needs landing tile
  surface/depth.

## 2. Damage multipliers on XA×YA damage (new support abilities)

- Routine: 0x80158300 (entry 0x80186580). Vanilla 0x80186568 is the shared
  "HP damage = XA × YA" step most damage formulas end in.
- ReMixed: damage × (100 + 20 if attacker has support bit 0x92&0x02
  [ability 0x1E4, Samurai/Draw Out RSM] + 50 if attacker has 0x91&0x10
  [slot 0x1D9 "Monster Talk", now a Dark Knight (Sing skillset) RSM] + 50
  if the TARGET has 0x91&0x10) / 100. So 0x1D9 = "deal +50%, take +50%".
  (It also loads target 0x92&0x01 but never uses it — dead code.)
- Then 0x8015F380 (entry 0x8018658C, same routine): if global 0x80190A04==1,
  ability has CT>0 and MP>0, attacker has 0x90&0x20 (slot 0x1D0) and
  current MP ≥ 2× the MP cost → damage ×2 (see §10, "second spell").
  Corrected 2026-11-03: 0x80190A04 isn't a flag but bytes 12–15 of unit
  0's name (+0x12C), never 1, and the CT and MP come from 0x80060000 +
  15 × id instead of the ability record (0x8005FBF0 + 14 × id), so the
  doubling never happens. It may have been meant for -2564(at), the AI's
  planning flag 0x8018F5FC.
- Then 0x80160E00 (entry 0x80186594): final HP damage × p/100 where p is a
  byte of the word at 0x80057774: byte 0 player, byte 1 enemy, bytes 2/3
  the same for Math Skill (skillset 0x15). p==0 means unchanged; result
  min 1. This looks like Power Modes (difficulty damage scaling).
- 0x80160D00 (reached from another agent's code): option 0x80057929&0xC0:
  0xC0 → all damage halved; 0x80 → player +25% / enemy −25%; 0x40 → the
  reverse. Another difficulty knob.
- Confidence: high for the arithmetic, medium for the option meanings.
- Remaster: post-process HP damage after the formula, before it's applied.

## 3. Death counter: undead revive and "no crystal" for allies

- Routines: 0x801581D8 (entry 0x80183170 via patched 0x80183150–0x80183170),
  0x801582C4 / 0x801582C8 (entries 0x80183160, 0x801831FC). Calls
  0x80157EC0 (other agent: per-unit counter +1, see §6).
- Vanilla: each turn a dead unit's counter (0x07) drops; at 0 it either
  revives (Undead, with a vanilla condition) or becomes crystal/treasure.
- ReMixed: counter 0xFF means frozen (never crystallizes). At 0: Undead
  units revive with ~50% chance (rand < 0x4000). Otherwise, for the
  player team: if option byte 0x80057927 & 0x22, or (no &0x01 and the
  unit isn't Ramza [base class 1–3, checked on 0x00 and 0x161]), the unit
  is marked permanently dead instead: counter=0xFF, innate status byte
  0x4E |= 0x20 (Dead), flags 0x06 |= 0x04. Enemies crystallize as vanilla.
  Each tick also bumps the per-unit counter at 0x80150284.
- Confidence: medium (option semantics guessed; the Ramza exception is clear).
- Remaster: hook the death-counter tick at turn processing.

## 4. Learn-on-hit from the secondary skillset

- Routines: 0x8015A004 (entry 0x8018E860), 0x8015A068 (entry 0x8018E8C8);
  patched lines at 0x8018E774–0x8018E7A8 save job/skillset to
  0x8015A000/0x8015A001.
- Vanilla: when a learnable ability is used, units with the "can learn"
  flag who have the ability in their current job's skillset (unit 0x12)
  and haven't learned it roll the ability's learn rate.
- ReMixed: after the primary scan, it rescans with the SECONDARY
  skillset (0x13), mapping skillset → job: generic skillsets 5..0x18 →
  job = skillset+0x45; 0x4D → Dancer job 0x5C; 0x4E → Bard/Dark Knight
  job 0x5B; anything else → Squire's bits. The learned bit is written to
  that job.
- Confidence: high.
- Remaster: hook "learn ability on hit" to also check the secondary set.

## 5. Ability animation table rewritten (lead 3 resolved)

- Routine: 0x80159D00 (+0x80159DB8 tail), called from 18 sites in the
  graphics code (0x800733EC, 0x80073978, 0x80074014, 0x800741B0,
  0x80077604, 0x8007A88C, 0x80082B34/BA0/C68, 0x800DA3EC, 0x800DA978,
  0x800DB014, 0x800DB1B0, 0x800DE604, 0x800E188C, 0x800E9B34/BA0/C68).
- Vanilla: 3 bytes per ability at 0x80093E10 (index×3 + 0/1/2).
- ReMixed format:
  - byte 2 now has its own 1-byte-per-ability table at 0x80159DCC.
  - bytes 0/1: index = 0x80093E10[ability] (1 byte per ability), then a
    halfword at 0x80093FD6 + 2×index: high 3 bits = number of variants,
    low 13 bits = offset into a byte pool at 0x800940BC. Variants are 3
    bytes [actor-type mask, anim0, anim1]; the first whose mask matches
    `1 << 0x80094749[actor[6]×4]` wins; otherwise a 2-byte default follows.
  - So animations can differ by actor type (likely monster/human
    families). The "01 01 01" filler the table tool saw is the new
    1-byte index list.
- Confidence: high on format, medium on what actor[6] means.
- Remaster: data only. Extract both tables to rebuild per-ability animation choices.

## 6. Event-script engine extensions (new event opcodes)

The largest part of the slice (0x80158400–0x80159D00, 0x8015A080,
0x8015A500–0x8015A680, 0x80160600) extends the battle event interpreter
(the opcode switch around 0x80143D0C/0x80145F24; s4 = opcode). These
matter only for porting ReMixed's own events/battles, not core mechanics.

- New variable ranges for event get/set (0x801586AC, 0x80158600,
  0x80158710, 0x80158764, 0x801597C0, 0x801597F8; entries 0x8014A0A0,
  0x8014A0E8, 0x8014A288, 0x8014A1CC, 0x8014A37C, 0x8014A3C8, 0x8014A110,
  0x80148FB8): 0x400–0x5FF bit flags, 0x600–0x9FF → bits at 0x80059414,
  0xA00–0xAFF → 2-bit fields at 0x800579C8, 0xB00–0xB7F → words at
  0x80165EF4. 0x80148FB8 also lets an event set bits in unit +0x1A7.
- New opcodes handled in 0x801588BC (entry 0x80143D3C), by s4 value:
  0x00–0x0E structured if/else/loop over event bytes (0xDB = block
  marker); 0xBF random number into a variable; 0x9F/0x17 read pad input;
  0xCC set byte 0x801502C0; 0xE7 reset the per-unit counters at
  0x80150284; 0xE8 find unit at (X,Y,level); 0xE9/0xEA read/write a map
  tile byte; 0xEA set camera/target fields (0x80165FD4..D8 + 0x8013D278);
  0xEB load an ENTD block from disc into 0x801DF000 and spawn up to 16
  units (reinforcements, via 0x80158400); 0x15 (re)spawn one unit from an
  ENTD entry, keeping chosen fields per flag bits; 0x9A clear unit bytes
  0x18C–0x1B6 for all units; 0x9B–0x9E push values into a ring at
  0x80165EF4; 0x8D set 0x80150299 (suppresses a call to 0x80183374, entry
  0x80141C48); 0xE6 count/adjust item stock across roster and inventory;
  0xC1/0xC4/0xC2 copy variables to/from event bytes; 0xC3/0xC5/0xC6 find
  a roster/battle unit by id; 0xC7 change a unit's job and recompute its
  raw stats from job growth/multipliers (0x8005E90C and job table);
  0xCD test whether a unit exists in the roster or the departed archive
  (§12); 0xCE write a halfword table; 0xED/0xEE load files from disc and
  copy 0x20 + 0x200 bytes into 0x800475E0 / 0x80049A18; 0xEF read a
  halfword from a loaded table; 0xCF unpack a bit-packed table into
  variables; 0xF0 call an arbitrary address given in the operands (jalr).
- New condition opcodes (0x8015996C, entries 0x80142B14/0x80142B24): set
  vars 0xBE/0xB0; count units in a rectangle (by team); Manhattan distance
  between two units vs N; per-unit counter (0x80150284) vs N; test any
  status bit on a unit; call 0x80183374.
- Other event hooks: 0x80159868 (0x8013ECD0, opcode 0x2F: toggleable
  loop flag bits at 0x80152AE0), 0x80159C90 (0x8013E968, opcode 0x9F
  pad test), 0x80159C5C (0x80132838, ENTD buffer "0xF2F2F2F2" reset),
  0x80159CD0 (0x8014938C, change a unit's level by ±N via 0x80157E00),
  0x8015A080 (0x80144970, battle reset: clears 0x8019FD50 and 0x800B7446
  arrays, sets vars 0x33 and 0x1FD), 0x8015A500 (0x80147744, optional
  vars 0x1D/0x20), 0x8015A560/0x8015A580 (0x80131E90/0x80131E68, message
  box override from 0x80057820 and portrait/sound index by flag bits),
  0x8015A600/0x8015A650 (opcode tails), 0x801583C0 (0x801455C8, unit
  removal also calls 0x801488A8 and clears 0x8019FD50[idx]), 0x80160600
  (swap two roster entries named by vars).
- Per-unit turn counter: 0x80159C04 (entry 0x80183C9C, CT-after-turn
  routine) adds 1 to 0x80150284[unit index] (saturating at 255) whenever a
  unit finishes a turn outside simulation. Events read it (turn-count
  triggers).
- Confidence: medium overall (opcode numbers certain, a few meanings guessed).
- Remaster: port only what ReMixed's events use; the remaster's event
  system is different.

## 7. Move-Find Item rework

- Routines: 0x8015C100 (entry 0x800F3658, map load), 0x8015C200 (entry
  0x80180278, item pick-up), 0x8015C300 (entries 0x800EAE6C, 0x800EB094,
  0x800EC8C4, 0x800ECA64, panel colouring). Data table 0x8015C000 (1
  byte per map). Works with in-place patches at 0x8018009C/0x801804C4
  (other agent).
- Vanilla: each map has up to 4 hidden tiles (0x800F5E74, 16 bytes/map).
  On a Move-Find unit landing there, the common item (byte 3) drops with
  Brave% chance, otherwise the rare one (byte 2); a per-map bit stops
  repeats.
- ReMixed:
  - On map load: if story progression (event var 0x6E) < threshold[map]
    (table 0x8015C000), the rare item is replaced by the common one, so
    rares are gated by story.
  - Found state per tile is kept in 4 bits per map at 0x80059414
    (persistent) plus a battle copy at 0x8015C0FF.
  - Pick-up still uses the Brave roll, but if the rolled variant was
    already taken it gives the other one.
  - Panels with hidden items are drawn in a different colour in the
    move-range overlay for units with Move-Find Item (0x95&0x01). The
    colour shows which variants remain; normal blue otherwise.
- Confidence: medium-high.
- Remaster: hook the move-find pickup and map load; colouring is optional UI.
- Read again 2026-11-04: byte 2 is the rare item and byte 3 the common one, which the roll (100 − Brave)
  gives on a hit; vanilla's save bits already stop a found panel for good, and ReMixed's make it give its
  common item again in later battles. The finding is ported (MECHANICS.md, Move-Find rework).

## 8. Status-infliction chance tiers (+ UI label)

- Routines: 0x8015C500 (entry 0x8018B928: category = 100 before each
  action's formula), 0x8015C700 (entry 0x80187F3C, the start of the status
  step 0x80187F24 itself, which every status application goes through; not
  formula 0x37 as first noted), 0x8015C540 (entry 0x8013527C, UI sprite). The chance byte 0x8015C514 is also written by
  0x801884D8 (patched: 0x13) and 0x8015D7D4 (60–74).
- Logic: the low nibble of the inflict-status record's flags byte (unused
  in vanilla) picks a chance: 0x8 → 75%, 0x4 → 50%, 0x2 → 25%, 0x1 → 10%,
  none → 100%. Values 0x13 and 60–74 are special categories set by
  formula code: 0x13 (19%) by 0x801884C0, which ReMixed now calls only in
  formula 0x02 (no status step follows it), and 60–74 by the unused 0x64
  engine. Outside simulation and when not "Separate", a failed roll is a
  miss (0x8018430C) and skips the step (to its epilogue 0x80188268). The
  outer step 0x80187EB4 restores the result's hit, type and chance, so
  through it only the statuses fail; the 17 direct callers (status-only
  formulas) miss.
- ReMixed also removed vanilla's 19% roll for a hit's statuses
  (0x801884C0, which rolls 0x13 with 0x80187690 and gates on result
  +0x10 & 0x200) from all five places vanilla calls it: 0x8018868C (the
  weapon chain's end), 0x8018872C, 0x801887D4 and 0x80189D4C become
  `or v0, zero, zero`; 0x80188CCC is in ReMixed's rewrite of formula 0x05
  (gun skills, 0x801529A0). Formula 0x02 gets the roll back at 0x80188BC4. The UI routine draws a small tag in the
  battle info window chosen by the category (100/75/50/25/10, 60–74, 19,
  0xFF).
- Confidence: medium (where else the chance is rolled is in the other
  agent's range).
- Remaster: data (flag nibble per inflict set) + a hit-roll hook.

## 9. Geomancy (Elemental) rework

- Routine: 0x8015D374 (entry 0x801896CC inside formula 0x23 Elemental),
  data table 0x8015D350 (3 bytes × 12).
- Vanilla: the surface type picks one of the 12 Elemental abilities.
- ReMixed (4 abilities left): even ability ids read the surface type at
  the selected panel; odd ids read the tile under the TARGET. The
  surface's vanilla Elemental entry (0x8005E9D0, minus 0x7E) indexes
  ReMixed's table [inflict-status id, element, effect id]. It sets the
  status set (and copies the inflict record), the element, and the
  ability's effect id in 0x801B63F0, then runs vanilla damage.
- Confidence: high.
- Remaster: hook Elemental formula; port the 12-entry table.

## 10. "Second spell" system (slot 0x1D0 = vanilla Gained EXP Up; Calculator innate)

Several pieces work together. The common thread is support bit 0x90&0x20
(ability 0x1D0, which ReMixed gives Calculator as innate) and a second
pending-action slot per unit at 0x8015E900 (8 bytes × 21:
CT, skillset, ability u16, target fields).

- Extra commands: 0x8015A140 (entry 0x801814D0, action-menu builder) adds
  White Magic (0x0A) and Black Magic (0x0B) as extra commands for units
  with 0x1D0, unless already primary/secondary.
- Menu filter: 0x8015E1D0 (entry 0x80181A18) and AI filter 0x8015F020
  (entry 0x8019A890) only allow, from those extra lists, spells with
  MP 1–15 and CT 1–5. The AI adds the lists too: 0x8015EFA0 (entry
  0x8019A490).
- Second charge: 0x8015DA60, 0x8015DE40, 0x8015E9C0 (entry 0x8018E164),
  0x8015EA00 (entry 0x80182BD8), 0x8015EAD0 (entry 0x80183880),
  0x8015EB20 (0x80183B5C), 0x8015EB50 (0x801835A0), 0x8015EB74
  (0x80068444), 0x8015EBD0 (0x8017AB14), 0x8015ED00 (0x80183694),
  0x8015ED80 (0x80181784), 0x8015EEC0/0x8015EEC8 (0x8017CABC,
  0x8007784C via 0x8015E0B0), 0x8015EF70 (0x8017CAC4), 0x8015DDA0/
  0x8015DDB0 (0x80183614, 0x8017C3CC), 0x8015E2A0/0x8015E2B4
  (0x801836D4), 0x8015F400 (0x8017DA64, 0x80183DE8), 0x8015F500
  (0x8017C3D4), 0x8015DEE0 (0x80183568).
  - A unit that already has a charging action can queue a second one.
  - Both CTs tick down each clock tick; when one finishes the other is
    resolved or promoted.
  - The charging-target display and CT order list show it.
  - Status changes that cancel charging also clear the queue (0x8015F400).
- Double damage with enough MP: §2 (0x8015F380).
- Also the action menu (0x8015A100, entry 0x80181494) shows command 4
  instead of Attack once the unit has acted (0x188&1) while a charge is
  pending (0x15D != 0xFF). 0x8015E260 (entries 0x801814B0/0x801814C0)
  hides skillset commands after state 0x188&8, and adds command 0x64
  after the Jump skillset (0x12).
- Confidence: medium. The queue mechanics are clear, but how the player
  gets the second cast and the exact rules (0x188 bits 0x01/0x02/0x08/0x80,
  0x187 0x80/0x90) need in-game testing. This is very likely the "Two
  Spells" feature from FEATURES.md.
- Worked out 2026-11-03 (MECHANICS.md, "Two Spells", has the rules): the
  first qualifying spell leaves +0x188 bit 7 clear, so the turn goes on;
  the slot isn't resolved by the clock but copied into the unit's record
  once the first action is over; the AI never takes a second action but
  casts each qualifying spell twice; and the doubling never fires.
- Remaster: hooks at action select, charge start, CT tick, charge resolve,
  and the command list.

## 11. Mounts / riding rework (chocobos and other monsters)

Vanilla supports riding chocobos (unit 0x182 link). ReMixed extends it:

- Mount skills: 0x8015A200 (entry 0x801814F0) adds the mount's primary
  skillset to the rider's command menu if the mount hasn't acted.
  0x80160F00 (entry 0x8018B974, formula dispatch) makes the MOUNT the
  real attacker when the rider uses a monster skillset (≥0xA8). Several
  checks use "rider and skillset ≥ 168 (0xA8)": 0x8015E100 (0x80071E18,
  sprite), 0x8015E150 (0x8017E86C), 0x8015DE40, 0x8015E3F0/0x8015E6A4.

## 14. Limit (skillset 0x29): faster charge at low HP

- Routines: 0x8015D8B0 (entry 0x8017C868, charge setup), 0x8015D480
  (entry 0x80181A6C, menu CT display).
- For Cloud's Limit skillset only: q = HP / (MaxHP/4) (min 1); charge CT is
  cut (3 − q) times by a quarter of the *original* CT (the quarter is computed
  once, before the loop), min 1 each time. HP ≥ 75%: unchanged; 50–75%:
  CT − CT/4; below 50%: CT − 2 × CT/4 (not ×0.5625: it doesn't compound).
  Short Charge still halves afterwards.
- Confidence: high.

## 16. "Hit Allies / Hit Enemies" flags now enforced

- 0x80160F00 (entry 0x8018B974, the jalr into the formula). Attribute
  byte 4 bits 0x80 / 0x40 (vanilla: AI and targeting only). 0x80 is on
  abilities that only help allies (Moogle, Fairy, the songs): a target on
  another team (0x1BA&0x30) is missed. 0x40 is on ones that only hit enemies
  (the attack summons): a target on the attacker's team is missed. The miss
  is 0x8018430C, and the formula doesn't run. Both bits are never set
  together (that would miss everyone). Also swaps attacker → mount (§11).
- Confidence: medium-high.
- Remaster: per-target filter in damage resolution.
