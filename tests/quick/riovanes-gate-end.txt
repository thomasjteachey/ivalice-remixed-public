# Rapha, too." it loads the guest Rafa's roster record (WorldUnitAddress) for the screens that follow, then takes her
# out of the party (DismissUnit, moved to her sprite set 0x29) before she rejoins as 0x29 (entry 0x1B2). A tester on
# 0.9.22 had the game close a few seconds after that line. WorldUnitAddress finds her by her name id (25, the 0x19 it
# names), not her sprite set: named 0x29 it found no one and the game closed on the same screens (seen here,
# 2026-11-19), so it stays 0x19 (tools/build_mod.py REMASTER_SPRITE_SET_OPS). Reported again on 0.9.31: its old-save
# repair removed 0.9.22's corrupt level-0 Rafa only on a world-map frame, while a gate battle autosave can resume
# without one. Event 281 now checks the record and clears a level-0 one at its point of use; its six Guest Departure
# pages run only for a valid record. This case injects the corrupt record after battle setup, bypassing both the world
# map and setup repairs, then proves the closing reaches event 282. Run with
